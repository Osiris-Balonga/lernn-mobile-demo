# i18n Rules (Paraglide JS)

## Setup

- Engine: `@inlang/paraglide-js` — compiled messages (zero runtime overhead)
- Config: `project.inlang/settings.json`
- Messages: `messages/{locale}.json`
- Generated output: `src/paraglide/` (auto-generated, DO NOT EDIT)
- Locales: `fr` (base/default), `en`

## Stratégie de locale

### Frontend — URL strategy

Paraglide utilise la stratégie `['url', 'baseLocale']` configurée dans `vite.config.ts` avec des `urlPatterns` personnalisés :
- **Toutes les locales** ont un prefix dans l'URL : `/fr/dashboard`, `/en/dashboard`
- La racine `/` redirige automatiquement vers `/{locale}/` (locale détectée ou `fr` par défaut)
- TanStack Router utilise un paramètre `$locale` à la racine du route tree

Le switch de locale se fait via le composant `LocaleSwitcher`. La locale courante est disponible via `getLocale()` depuis `#/paraglide/runtime`.

### Navigation avec locale

Toute navigation doit inclure le paramètre `locale` :
```typescript
import { getLocale } from '#/paraglide/runtime'

// Dans un beforeLoad
throw redirect({ to: '/$locale/login', params: { locale: params.locale } })

// Dans un composant
navigate({ to: '/$locale/select-profile', params: { locale: getLocale() } })

// Via getProfileRoute (helper)
const route = getProfileRoute(profile, getLocale())
navigate({ to: route.to, params: route.params })
```

### Backend — Query param

Le backend lernn-api accepte la locale via :
1. Query param `?locale=fr` (prioritaire)
2. Header `Accept-Language` (fallback)

Pour les appels API qui ont besoin de localisation (emails, messages d'erreur) :
```typescript
import { getLocale } from '#/paraglide/runtime'

apiClient.post('/students', data, {
  params: { locale: getLocale() },
})
```

## Usage

```typescript
import * as m from '#/paraglide/messages'

// Simple message
<h1>{m.dashboard_title()}</h1>

// With parameters
<p>{m.welcome_user({ name: user.firstName })}</p>

// Plurals and formatting handled in message definitions
```

## Message File Format

`messages/fr.json`:
```json
{
  "dashboard_title": "Tableau de bord",
  "welcome_user": "Bienvenue, {name}",
  "students_count": "{count, plural, =0 {Aucun élève} one {# élève} other {# élèves}}",
  "nav_students": "Élèves",
  "nav_payments": "Paiements",
  "action_save": "Enregistrer",
  "action_cancel": "Annuler",
  "action_delete": "Supprimer",
  "error_required": "Ce champ est requis",
  "error_invalid_email": "Adresse email invalide"
}
```

## Naming Convention for Keys

Pattern: `{scope}_{descriptor}`

| Prefix | Usage | Example |
|--------|-------|---------|
| `nav_` | Navigation items | `nav_students`, `nav_dashboard` |
| `action_` | Buttons, actions | `action_save`, `action_delete` |
| `label_` | Form labels | `label_first_name`, `label_email` |
| `error_` | Validation/error messages | `error_required`, `error_not_found` |
| `toast_` | Toast notifications | `toast_student_created` |
| `title_` | Page/section titles | `title_student_list` |
| `desc_` | Descriptions, help text | `desc_onboarding_step1` |
| `placeholder_` | Input placeholders | `placeholder_search` |
| `status_` | Status labels | `status_active`, `status_paid` |
| `confirm_` | Confirmation dialogs | `confirm_delete_student` |
| `col_` | Column headers (tables) | `col_name`, `col_email` |

## Rules

1. **NEVER** hardcode user-facing strings — always use `m.key()`
2. **ALWAYS** add both `fr` and `en` translations when creating new keys
3. **NEVER** edit files in `src/paraglide/` — they are auto-generated
4. **USE** flat key structure (no nesting) — Paraglide uses flat JSON
5. **PREFER** descriptive keys over generic ones: `toast_student_created` not `success_message`
6. **French is the primary language** — write FR first, then translate to EN
7. **Run** `pnpm dev` to regenerate Paraglide output after adding messages
8. **PASS** `locale` en query param pour les appels API backend qui ont besoin de localisation

## Server-Side

For server functions, pass locale explicitly:
```typescript
export const getServerData = createServerFn({ method: 'GET' })
  .validator(z.object({ locale: z.enum(['fr', 'en']) }))
  .handler(async ({ data }) => {
    // Use data.locale for server-side i18n if needed
  })
```
